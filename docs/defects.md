BUG-001 - Потеря срока выполнения при редактировании заявки

Компонент: TicketService
Метод API: PATCH /api/tickets/{id}
Приоритет: Medium
Статус: Исправлен, модульный регрессионный тест пройден

Описание

При частичном редактировании заявки ранее установленный срок выполнения сбрасывался в null, если поле dueAt отсутствовало в JSON-запросе.

Шаги воспроизведения

1. Создать заявку с приоритетом HIGH и сроком 2026-12-30T18:00:00.
2. Выполнить PATCH-запрос, передав новое описание и приоритет MEDIUM, но не передавая dueAt.
3. Получить заявку через GET /api/tickets/{id}.
4. Проверить значение поля dueAt.

Ожидаемый результат

Срок выполнения остаётся прежним, поскольку клиент не запрашивал его изменение.

Фактический результат до исправления

Сервер возвращал HTTP 200, но поле dueAt становилось null.

Дефект воспроизведён через REST API 17 ноября 2026 года.

Причина

Метод TicketService.updateTicket() безусловно присваивал значение request.getDueAt().

Когда поле отсутствовало в JSON, его значение в DTO было равно null, что приводило к удалению ранее установленного срока.

Исправление

В UpdateTicketRequest добавлены признаки присутствия необязательных полей:

* descriptionProvided;
* dueAtProvided.

В TicketService.updateTicket() изменение соответствующих полей теперь выполняется только в том случае, когда они присутствуют в запросе.

При этом сохранена возможность явно удалить срок, передав "dueAt": null.

Регрессионное тестирование

Модульный тест: TicketServiceTest.testUpdatePreservesDueAtWhenOmitted()

До исправления тест завершился ошибкой AssertionFailedError.

После исправления повторный запуск завершился BUILD SUCCESSFUL.

Полный запуск spotlessCheck clean test jacocoTestReport также завершился успешно.

Интеграционный тест: TicketIntegrationTest.testPatchPreservesDueAtWhenOmitted()

Проверяет сохранение срока при частичном обновлении заявки через REST API. Результат необходимо зафиксировать после выполнения полного тестового набора.

Результат

Потеря срока устранена на уровне сервиса. Дополнительная интеграционная проверка подтверждает корректность обработки HTTP-запроса после её успешного выполнения.
