## 4. Известные ограничения проверки

### Временное окружение CD

Автоматическое развёртывание выполняется на GitHub-hosted runner с операционной системой Ubuntu.

После завершения задания контейнеры останавливаются. Постоянное размещение приложения на отдельном сервере не выполнялось.

### Ручной откат

Возврат к предыдущей версии Docker-образа проверен на локальном Docker-стенде.

Автоматическая процедура rollback в GitHub Actions не реализована.

### Сквозное тестирование

Сквозные бизнес-сценарии выполняются через Spring MockMvc с использованием тестовой базы данных.

Проверка через отдельный внешний HTTP-клиент не входит в состав автоматизированных сквозных тестов.

### Проверка восстановления базы данных

Выполнена проверка успешности восстановления, количества заявок, категорий и истории миграций Flyway.

Полное побайтовое сравнение содержимого исходной и восстановленной баз не проводилось.

## 5. Журнал дефектов

В ходе тестирования обнаружен и исправлен дефект **BUG-001**, связанный с некорректной обработкой частичного обновления заявки.

### BUG-001 - потеря срока выполнения заявки при редактировании

| Параметр | Описание |
|---|---|
| Идентификатор | BUG-001 |
| Компонент | `TicketService` |
| Метод API | `PATCH /api/tickets/{id}` |
| Приоритет | Medium |
| Статус | Исправлен |
| Причина | Безусловное присваивание значения `request.getDueAt()` |
| Исправление | Проверка присутствия необязательных полей в запросе |
| Результат | Срок выполнения сохраняется, если поле `dueAt` отсутствует |

### Воспроизведение дефекта

1. Создать заявку с установленным сроком выполнения.
2. Выполнить PATCH-запрос, изменив описание и приоритет без передачи поля `dueAt`.
3. Получить обновлённую заявку через GET-запрос.
4. Проверить сохранённое значение `dueAt`.

**Ожидаемый результат:** ранее установленный срок выполнения сохраняется.

**Фактический результат до исправления:** значение `dueAt` сбрасывалось в `null`.

### Причина возникновения

Метод `TicketService.updateTicket()` безусловно присваивал значение `request.getDueAt()`.

Если поле `dueAt` отсутствовало в JSON-запросе, его значение в DTO было равно `null`.

В результате ранее установленный срок выполнения удалялся.

### Реализованное исправление

В классе `UpdateTicketRequest` добавлены признаки присутствия необязательных полей.

В методе `TicketService.updateTicket()` реализована проверка наличия соответствующих полей в запросе перед обновлением.

Если поле `dueAt` отсутствует, исходный срок выполнения сохраняется.

Если клиент явно передаёт `"dueAt": null`, срок выполнения может быть удалён.

### Регрессионное тестирование

Для проверки исправления реализованы два теста:

| Тест | Тип | Результат |
|---|---|---|
| `testUpdatePreservesDueAtWhenOmitted` | Модульный | Успешно |
| `testPatchPreservesDueAtWhenOmitted` | Интеграционный | Успешно |

До исправления модульный регрессионный тест воспроизводил обнаруженную ошибку.

После исправления модульный и интеграционный тесты завершились успешно.

Повторное выполнение полного набора из 27 автоматизированных тестов также завершилось без ошибок.

**Итог:** дефект BUG-001 устранён. Корректность исправления подтверждена регрессионным тестированием.

Подробная информация представлена в [журнале дефектов](defects.md).
