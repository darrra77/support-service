4. Известные ограничения проверки

* Временное окружение CD. Автоматическое развёртывание выполняется на GitHub-hosted runner. После завершения задания контейнеры останавливаются. Постоянный сервер не используется.
* Ручной rollback. Откат Docker-образа проверен на локальном стенде. Автоматический откат в GitHub Actions не реализован.
* Сквозное тестирование. Бизнес-сценарии выполняются через MockMvc с использованием тестовой базы данных, а не через отдельный внешний HTTP-клиент.
* Восстановление данных. Проверены успешность восстановления, количество заявок, категории и история миграций. Полное побайтовое сравнение баз данных не проводилось.

5. Журнал дефектов

В ходе тестирования обнаружен и исправлен дефект BUG-001.

BUG-001 - Потеря срока выполнения заявки при частичном обновлении

Компонент: TicketService

Метод API: PATCH /api/tickets/{id}

Статус: исправлен.

Описание дефекта

При редактировании заявки ранее установленный срок выполнения (dueAt) сбрасывался в null, если поле отсутствовало в JSON-запросе.

Шаги воспроизведения

1. Создать заявку с установленным сроком выполнения.
2. Выполнить PATCH-запрос, изменив описание и приоритет без передачи dueAt.
3. Получить обновлённую заявку через GET-запрос.
4. Проверить значение dueAt.

Ожидаемый результат

Ранее установленный срок выполнения сохраняется.

Фактический результат до исправления

Срок выполнения сбрасывался в null.

Причина

Метод TicketService.updateTicket() безусловно присваивал значение request.getDueAt(), даже если поле отсутствовало в запросе.

Исправление

В UpdateTicketRequest добавлены признаки присутствия необязательных полей.

Логика TicketService.updateTicket() изменена таким образом, чтобы обновлять необязательные поля только при их присутствии в запросе.

При этом сохранена возможность явно удалить срок выполнения, передав "dueAt": null.

Регрессионное тестирование

Для проверки исправления используются два теста:

Тест	Назначение	Результат
testUpdatePreservesDueAtWhenOmitted	Проверка бизнес-логики сервиса	Успешно
testPatchPreservesDueAtWhenOmitted	Проверка частичного обновления через REST API	Успешно

До исправления модульный регрессионный тест воспроизводил дефект и завершался ошибкой.

После внесения изменений оба регрессионных теста успешно проходят.

Полный набор из 27 автоматизированных тестов также выполняется без ошибок.

Подробное описание дефекта представлено в журнале дефектов http://defects.md.

## 4. Известные ограничения проверки

- GitHub-hosted runner — временная среда: после завершения задания контейнеры уничтожаются. Это не постоянный учебный стенд.
- Скриншот успешного workflow не подтверждает все граничные случаи бизнес-логики; их необходимо сопоставить с кодом тестов.
- Откат предыдущей версии образа отдельно не продемонстрирован.
