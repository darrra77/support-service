# Тест-план Support Service

## 1. Цель и область тестирования

Цель — проверить функциональные требования REST API службы поддержки, Kotlin-отчётность, сохранение данных в PostgreSQL и воспроизводимость сборки. Основание: задание на практику, раздел 6, и `docs/requirements.md`.

## 2. Среда и инструменты

- Java 21, Spring Boot 3.5.x, Kotlin, Gradle.
- JUnit 5, Mockito; интеграционные тесты с PostgreSQL через Testcontainers.
- PostgreSQL 16, Flyway, Docker Compose.
- JaCoCo для покрытия; GitHub Actions для CI/CD.

## 3. Критерии входа и выхода

**До начала:** зависимости скачиваются, Docker доступен для Testcontainers, миграции создают необходимую схему.

**Успешное завершение:** команды `./gradlew spotlessCheck` и `./gradlew clean build jacocoTestReport` выполнены; нет падающих тестов; результаты, покрытие и лог запуска сохранены; обязательные граничные случаи подтверждены тестами.

## 5. Обязательные количественные требования из ТЗ

- Не менее **10 модульных** тестов.
- Не менее **6 интеграционных** тестов с PostgreSQL/Testcontainers.
- Не менее **2 сквозных** сценариев.
- Не менее **3 тестов на Kotlin**, включая один тест Java-компонента.
- Обязательный регрессионный тест для исправленного дефекта.

Количество тестов и соответствие категориям подтверждаются **перечнем фактических методов тестирования**, а не одной общей цифрой.

## 6. Команды выполнения

```bash
./gradlew spotlessCheck
./gradlew clean build jacocoTestReport
open build/reports/tests/test/index.html
open build/reports/jacoco/test/html/index.html
```

Для проверки CI/CD: GitHub → Actions → успешный запуск `Support Service CI` → jobs `Build and Test`, `Publish Docker image`, `Deploy and Verify`.
